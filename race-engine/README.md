# 共通・条件回帰ループ 3D 競馬シミュレーター

**同じ画面・馬モデル・走行アニメーション・採点・着順シミュレーションを、レース設定ファイルだけで流用するためのエンジンです。**

## 馬群の走行ライン pack-v1（2026-10-22）

馬番固定の平行レーンを廃止。前馬の後ろ、ラチへの寄り、コーナーの距離、空いた進路を評価し、馬体占有領域と移動途中の交差を検査する経路計画を追加。2D・3D・カメラで同じ進路を使用する。抽選済みの着順を保つ映像用モデルで、詰まりや消耗による勝率を新たに推定するものではない。

調査の根拠・仮定・限界は [設計ノート](docs/pack-dynamics.md)。単体検証は `node race-engine/tests/race-pack.mjs`。実画面との座標一致は `tests/kikka-browser.mjs`。既存の4倍速・ばらつき3・即ゴール・5カメラ・実況を維持する。

## 走行モーション v16

## 新しいレースの登録手順

1. `race-engine/races/sample-demo.js` をコピーし、`<race-id>.js` として追加
2. `id`、`name`、`date`、`venue`、`raceNumber`、`surface`、`distance`、`course` を入力
3. `horses` に**確定した出走馬を馬番順で3〜18頭**入力（取消・除外反映）。`no` は1からの連番。確定時は各馬の `frame` に公式の枠番号1〜8を登録（不明なら `provisionalDraw:true` として帽色を灰色表示）
4. 過去走や調教等の証拠があるときだけ `inputs` を追加。情報がない場合は省略し、中立点とする
5. 必ず `demo:false` を指定し、出馬表などの一次資料を `notes` や `sources` に記載
6. コミットすると GitHub Actions が検証・公開。`/race-engine/?race=<race-id>` を開く

### 設定ファイルの最小構成

```js
export default {
  schemaVersion: 1,
  id: 'example-2026',
  name: '対象レース名',
  shortName: '略称',
  date: '2026-10-12',
  venue: '東京',
  raceNumber: 11,
  surface: '芝',
  distance: 1800,
  course: '左回り',
  courseView: 'generic', // 京都芝1400m外のみ 'kyoto-1400-outer'
  duration: 105,
  demo: false,
  notes: '出走馬・騎手・枠順を確認済み。未取得要素は中立。',
  horses: [
    // {no:1,frame:1,name:'...',age:'牡4',kg:57,j:'...',trainer:'...',
    //  father:'...',mfather:'...',rest:null,training:null,
    //  style:'好位',base:null,sd:10,history:'...',plus:'...',minus:'...'},
    // ... 馬番2〜末尾まで
  ],
  inputs: {
    // 馬番: [同コース,ラップ,父/母父の暫定血統,厩舎,距離適性]
    // 必要な証拠なしに数値を埋めないこと
  },
  speedAdapt: {}, // 超高速馬場の適性。根拠がないとき空
  factors: {
    // draw: [null,{n: 出走数,p3: 3着以内数},...],  // 該当コースの過去データだけ
    // sex: {female:{n:出走数,p3:3着以内数},other:{...}},
    // riders: {'騎手名':[1着,2着,3着,その他]},
    // riderROI: {'騎手名':複勝回収率}
  }
};
```

**注:** 上の構成には、現状のツールで取得済みのデータがない箇所を含めません。人気・オッズの模倣や架空の調教・血統点を作らないでください。確率は未校正のモデル内出現率であり、実的中確率を意味しません。

## 共通ルール：JRAの騎手帽色（以後の全レースに適用）

騎手の**ヘルメットの色は馬番ではなく枠番号**で決めます。馬主の勝負服色、馬体の毛色、脚質・人気などと混同しないこと。

| 枠 | 帽色 | 実装色（画面表示用） |
|---:|---|---|
| 1 | 白 | `#FFFFFF` |
| 2 | 黒 | `#111111` |
| 3 | 赤 | `#E62931` |
| 4 | 青 | `#1561C2` |
| 5 | 黄 | `#FFD600` |
| 6 | 緑 | `#009944` |
| 7 | 橙 | `#F28C00` |
| 8 | 桃 | `#EE8FAB` |

- 唯一の共通色定義は [`core/jockey-caps.js`](core/jockey-caps.js)。3Dアニメ騎手帽（頭頂・正面・つば）、2Dの馬番マーカー、8枠の凡例に使用。勝負服 `silkHex` は独立で、帽色に転用しません。
- **確定枠順がある場合**は設定ファイルの各 `horse.frame` を優先。`frame` がない旧レースは共通 `core/factors.js` の馬番→枠変換を利用。
- **枠順未確定**では必ず `provisionalDraw:true` にし、仮番号から枠を推測しない（帽は灰色 `#89929B`、凡例に未確定表示）。確定後は `horse.no` と `frame` をJRA出馬表と照合して `provisionalDraw:false` に更新。
- JRAの例外：同枠かつ同じ勝負服の場合、規程により「四ツ割（枠色＋白、1枠のみ枠色＋水色）」「八ツ割」の染め分け帽が使われることがあります。**公式に確認できた場合のみ**対象馬に `capPattern:'quartered'` または `capPattern:'eighths'` を設定。自動推測はしません。3Dは球面セクター分割で表現します。
- 1枠白、2枠黒、5枠黄、8枠桃でも背景から識別できる縁取りと馬番の適切なコントラストを使用。色のhex値は表示用の近似色で、JRAがデジタルRGB値として指定したものではありません。
- すべての新レース登録時に帽色自動テストを実施すること。馬の登録順の並べ替えや取消・除外時にも、`no` にひもづく勝負服色を帽色に流用しない。

一次資料：[JRA・競馬用語辞典（帽色）](https://www.jra.go.jp/kouza/yougo/c10040_list.html)、[JRA・本会が定める帽色および染め分け](https://www.jra.go.jp/keiba/program/2023/pdf/bangumi_betsu.pdf)。

## 評価点のバランス・重複減点回避ルール（2026-10-16追記）

- **未経験の条件と不向きの証拠を混同しない**。未走距離や初コースを、コース適性・血統・距離適性で同じ理由から3回減点することを禁止。代替証拠（近接距離の実走、追走ラップ、母系の実績）を確認し、未確認リスクは条件別シナリオと不確実性で表現する。
- GIIや条件戦の勝利は着差だけでなく、前半1000mと終い3F・走行位置・仕掛け・重馬場での実戦・前走相手関係を照合する。スロー前残りだけと誤認しない。
- 調教／能力／騎手／枠／血統の**異なる証拠**を独立して採点し、既に高評価済みの要素を再加点しない。
- 他馬にも同じ原則を適用し、基礎モデルと別採点案の結果を固定シードで比較。ユーザーの好みや人気・オッズに合わせて逆算しない。未校正の出現率を確率の精度と誤認しない。
- 2026秋華賞の[モンローウォークの評価監査](reports/shuka-2026-20261016-monroe-review.md)では、ローズS1000m58.9秒・2番手・上がり34.1秒・0.5秒差のノーステッキ勝ちと[JRA-VANの血統検証](https://jra-van.jp/fun/tokusyu/g1/shuka/bloodline.html)に基づいて、course75→79、lap87→89、blood68→84、distance66→74、sd9→10と限定修正した。他16頭の採点はそのまま。

- リッチな3D WebGLのCDNに障害があった場合もSVGフォールバックを維持。集中表示はUIの操作であり、実測京都内回り3Dや物理演算を新設したものではない。

### ギャロップ動作 v12（2026-10-17）

- `config.direction` に応じ右手前・左手前を切替。最後の直線では描画上の手前替えを表現し、各馬 `leadChangeAt`（0〜1の進捗度）で切替位置を設定可能。未指定は `.82`。**実際の馬の手前を観測したものではなく、演出上の仮定**。

### 4拍子モーション v13：左右脚の同期表示問題を修正（2026-10-17）

- **症状**：前脚2本・後脚2本が、横から見ると同時に振れているように見える。旧v12の脚の前後移動は約0.53mと小さく、長い回収補間と16倍速時の速いアニメーションが原因候補。
- **改善**：接地中の蹄軌跡を前後1.24mへ拡大。独立した4本の脚について蹴り・屈曲・前方回収を別々に補間。肢の骨長を伸ばし、近側・遠側の毛色明度差を設ける。馬同士の周期も分散。
- **時間制御**：アニメーション時間を描画フレームの実経過秒から計算し、16倍速時でも脚運びを約2ストライド/秒に抑える。再生停止中は脚の位相も停止。
- **見分けるための画面**：[4拍子・ギャロップ動作検証](gait-lab.html)。本編と同じ `horse-anime.js` / `chibi-gallop.js` を使い、0.25倍速、コマ送り、横/斜前/正面で接地順を確認できる。
- **再発防止**：`tests/smoke.mjs` は左右の肢の角度差・低FPSでの視認性を、`tests/mobile-browser.mjs` は実WebGL再生中の前後肢の角度差と見えるバージョン表示を確認する。予想・着順計算には変更なし。

## 走行モーション v14：写真から計測された馬の関節角度に基づく実装（2026-10-17）

**v12/v13の蹄目標IK（カニ走りを引き起こした2関節近似）を廃止。** 12連続写真に基づく角度データを4関節の脚モデルに適用し、周期的に補間する。足の角度を適当に回転させる方式ではない。

- 研究資料：[モーション動物園](https://motionzoo.net/horse-gallop-reference/)、[Muybridgeの16連続写真（NGA）](https://www.nga.gov/artworks/167044-plate-number-626-annie-g-galloping)、[UBCの2002年馬ギャロップ2Dモデル](https://www.hemispheregames.com/eddybox_cs_ubc/projects/533B/index.html)、[その12姿勢の計測関節角度](https://www.hemispheregames.com/eddybox_cs_ubc/projects/533B/angles.txt)、[馬のtransverse gallopの力学](https://pmc.ncbi.nlm.nih.gov/articles/PMC2696142/)。
- `assets/equine-motion-frames.js`：上記UBCの角度数値18列×12行を収録。各脚4セグメントの相対角度をCatmull–Romでループ補間。左手前は左右の脚ブロックを交換する。
- `assets/horse-anime.js`：前肢は肩・前腕・管・蹄、後肢は大腿・下腿・管・蹄の4節リグに再設計。X方向に左右へ振る「カニ走り」はしない。全脚の回転軸は前後の矢状面。
- `assets/chibi-gallop.js`：足先目標への2ボーンIKを廃止し、写真計測データから骨格角度を直接アニメーション。最小蹄高で胴体位置を調整。実時間に沿って周期更新するので16倍速でストロボ化しない。左手前/右手前は左右対称に反転。
- `gait-lab.html`：本編と同一の馬モデルを独立表示して、0.25倍/0.5倍/1倍、コマ送り、前後/真横視点で確認。
- `tests/smoke.mjs`：写真12姿勢、左右手前、継ぎ目、4関節、浮遊、停止、倍率非依存の回帰テスト。`tests/mobile-browser.mjs`：実WebGL再生中の四肢角度差と画面描画を検査。

**限界**：2D写真から測られた関節角度を3Dに転用した近似。実際の競走馬の個体差、撮影角度からの奥行き推定、体幹の正確な3D変形、蹄の地面への完全固定、レース映像との同一フレーム比較は未検証。目視の完成判定は実機WebGLで行う必要がある。予想ロジックは変更していない。

## ギャロップ v15：カニ走り対策の骨格・動作の再設計（2026-10-17）

v14の『相対角度を細い4本の筒に累積回転』する描画は、接地順の数値検査に通っても、角張った脚が横に突き出して見えるため廃止。ユーザーによる3D実画面の指摘（v14の2コーナー正面）を再現不具合として扱う。

- `assets/equine-gallop-v15.js`：**右手前**を例に、左後(.00)→右後(.16)→左前(.33)→右前(.49)の順で接地。各脚の地面支持は約.19ストライド、.68〜1.00には4蹄が離地する単一浮遊期。左手前は同じ動きを左右で入れ替える。
- 前脚は肩→肘→前膝（carpus）→球節→蹄、後脚は股関節→膝（stifle）→飛節（hock）→球節→蹄の**関節点座標**をそれぞれ計算。背中から4本の長い棒を回転させる方式は使わない。走行は進行方向と上下方向のみ（X方向へ脚を開かない）。
- `assets/horse-anime.js`：脚を端点間の太さ付きテーパーメッシュに再構成。前脚/後脚の太さを区別し、各膝に関節ボリューム、先端に独立した蹄を設置。
- `assets/chibi-gallop.js`：独立した4つの脚のポイントを補間し、前肢の回収と後肢の蹴りを別々に再現。胴体/首/騎手も軽く連動。16倍速でも画面上のギャロップ周期は実時間で制御。
- [1頭表示の検証画面](gait-lab.html)：再生・一時停止・コマ送り・0.25倍速・右/左手前・真横/斜め/正面視点を確認。
- `tests/smoke.mjs`：実際に離地する区間、4脚の接地順、馬の前後肢関節と脚同士の位相差、アニメ停止、18頭の共通モデル保持を追加。`tests/mobile-browser.mjs`：本編WebGLの左右の蹄位置差を検査。

**検証上の限界**：2D骨格の姿勢画像は作成して目視したが、GitHub Pages本番でのThree.js WebGL動画の人間による最終確認は未完。テーパーメッシュ化は実馬のフォトグラメトリ/モーションキャプチャではなく手続き型アニメーション。脚の各節長は厳密固定ではない。馬体は旧モデルを流用し、高精細な実馬モデルとは異なる。新しいギャロップは予想・着順モデルに影響しない。
