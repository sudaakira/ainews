# リニューアル rebuild-v17（2026-11-03）— 描画・歩様・カメラの全面見直し

計算（core の採点・回帰・モンテカルロ、レース設定ファイル、pack-v1 の経路計画）には**一切触れていない**。変えたのは提示層のみ。内部リビジョン名：歩様 v20（v19 の後継）、馬体シェーディング v25（v24 の後継）。

## 1. 歩様の「滑り足」解消 — `assets/gallop-sync.js`（新設）+ `assets/chibi-gallop.js`

- v19 クリップの実測：`sprint-motion-v19.json` の接地脚（y が最小付近のサンプル）の z 移動量から、クリップが想定する対地速度は FL≈17.3 / FR≈16.8 / HL≈16.1 m/s（平均≈16.7）。クリップ長 0.42s → 制作時ケイデンス 2.381 stride/s、**制作時ストライド長 ≈7.03m**。
- 旧実装は `speed/7.1` を 2.20–2.65 にクランプしており、低速域（12m/s で脚の対地速度が約15m/s）では蹄が地面を滑っていた。
- 新実装はストライド長を一定とし `cadence = clamp(speed / 7.03, 1.30, 2.78)`。**10.2–19.5 m/s の実走域では滑り率 0%**（数値検証済み）。クランプ域外（発走直後の極低速・21m/s 超）だけ誤差が残るが、発走直後は idle ブレンド（active ランプ）が覆う。
- `model.gallopAudit` に `strideLength` と `slipRatio` を追加し、画面側から常時監査できる。

## 2. 二次運動（同じく gallop-sync.js の `secondaryMotion`）

位相から次を生成し、`horse-anime.js` の `pose()` 第5引数で適用（旧呼び出しは省略可＝後方互換）。

- 体幹：bob 最大 ±3.3cm、pitch 最大 ±1.6°。浮遊期（位相 .78–1.00）に体が上がり、後肢接地で沈む。
- 首・頭：pitch に逆位相の nod（Neck3 55% / Head 45%）。鬣は首ボーン追随で自動的に揺れる。
- 尾：Tail1/Tail3 に位相遅れ付き sway。
- 騎手の追い：伸展期に肩が最大 +5.2cm 前へ、座りが +2.2cm。鞭は元々モデルに無く、追加していない（「控えめに自然に」の範囲で、腕を上げる演出は入れない判断）。
- ゼッケン：馬名フォント 105→118px、テクスチャ anisotropy 8→16。gait-lab 近接でも番号・馬名が読めることを確認。

## 3. 馬体の陰影 — `assets/thoroughbred-body.js`（頂点カラーのみ）

背線のトップライト、腹帯の溝の深化、肩・臀部筋肉部の増光を頂点カラーに加えた。**頂点位置は不変**（シルエット・骨格・鞍位置への影響なし）。

## 4. 光・影・空 — `renderer.js`

- `NoToneMapping` → **ACES Filmic**（露出 1.12、 hemisphere 1.8 / sun 2.4 に引上げて補償）。素材間でバラついていた色調を統一。
- **実シャドウマップ**（PCFSoft、単一カスケード）を新設。太陽は毎フレーム先頭集団の注視点へ追随し、±62m の正射影範囲だけを描く。解像度はモバイル 1024 / その他 2048。馬（毛・付属・ゼッケン・騎手）は cast、コース面・内馬場リボン・地面は receive。塗りの blob 影は接触影として 45% に減衰して併用。
- 霧は FogExp2 → 線形 Fog(220–1500m)。背景はグラデーションのスカイドーム（fog 無効、カメラ追随）に変更し、地平線の色抜けを解消。
- 芝テクスチャの刈り込みストライプのコントラストを強化（帯の明暗差を拡大＋帯境のハイライト）。
- ラチに下段レール（高さ .42m）を追加。
- 発馬機：開扉を .65s → **.50s**、ease-out cubic＋5% の行き過ぎでバネ感を付けた。

## 5. カメラのカット切替ブレンド — `renderer.js`

- ショット構成そのもの（`race-shotlist.js` の5カット、locked dolly、4C 固定カメラ）は不変。被写界深度は未実装のまま、霧と色調で代替（従来方針を維持）。

## 追補 v17.1（2026-11-03、公開CI失敗の修正）

初回コミット（95202b0）は公開ワークフローのブラウザ検証（mobile-browser の gait-lab 節）で失敗した。原因は二次運動の追加ボブ（±30mm）と中心ピボットのピッチ（±0.021rad）が、v19クリップの接地マージン（最低蹄 +6mm）を食い潰し、接地蹄が芝を最大34mm貫通していたこと（gait-lab 実測で特定）。

修正は `assets/gallop-sync.js` の `secondaryMotion` のみ:
- ボブを持ち上げ専用に再設計（接地中はベイク済み高さ、飛行局面で最大 +26mm のリフト）。沈み込み方向の追加変位を廃止。
- ピッチ振幅を約半分（±0.012rad）にし、ボブへ |pitch|×1.35m の補償リフトを加算。下がる側の蹄がベイク済み蹄ラインを下回らない構造にした。

再検証: gait-lab 全12条件（左右リード×6位相）で最低蹄高 ≥ +6.0mm、飛行位相 .9 で +136.6mm（閾値 +35mm）、ページエラーなし。ノードテスト全6スイート再合格。CI と同じ4ブラウザスイート（mobile / kikka / takarazuka / tenno）をローカル再現環境で全て合格させてから再コミットする。

## v17.2 追記（2026-11-03、v18 却下に伴う既定エンジン復帰と2点の移植）

手続き生成で全面再構築した v18（renderer-v18.js ほか）は、ユーザーの実機視聴で「走り方もモデリングもすべてめちゃくちゃ」と却下された。数値監査（滑りゼロ・重なりゼロ）を通っても見た目の説得力がなければ意味がない、という判断である。これを受けて既定エンジンを v17.1（コミット 7a5b423 の状態）へ戻し、v18 で得た技術のうち原因のはっきりした2点だけを v17 系へ移植した。v18 のファイル群は削除せず、`index.html` の切替で `?engine=v18` のときだけ読み込む任意選択として残置する（既定は `renderer.js`、キャッシュバスト文字列は従来どおり）。

### 移植A：歩様位相のレース時計ロック（assets/chibi-gallop.js）

- 欠陥：従来の `updateGallop` は位相を実時間 `frameDt`（上限 .06 秒）で進めていた。レース時計は再生倍率ぶん速く進むため、既定の4倍速では脚の回転が対地移動の約1/4しかなく「ノロい・滑空する」見た目になっていた（app.js の visualTime も同様の圧縮だった）。
- 移植：位相増分を「レース時計の増分 × cadence（その瞬間の対地速度から導出）」に変更。後方シークは従来どおり状態リセット、大きな前方ジャンプ（>0.5 秒）はレース時計から位相を決定論的に再導出（seed + raceTime × cadence）し、シーク・リプレイの決定性を維持する。gait-lab はレース時計が固定の検査ツールのため、時計が進まない場合に限り従来の frameDt 駆動を残した（レース描画中にこの分岐が使われることはない）。
- 監査（tests/smoke.mjs に追加）：renderer と同じ呼び出し条件（レース時計 = 倍率 × 実時間、frameDt = 実 dt、visualTime は app.js の式）で倍率4・16を駆動し、(1) 1フレームの位相進行が cadence ×（レース時計増分）と一致（許容 1e-9）、(2) 接地蹄の対地速度誤差が 0.02 m/s 未満、を検証。
- 読み替えの注記：v18 の手続き歩様は audit の `groundSpeedError = |ストライド長 × cadence − 速度|` を持つ。v17 の歩様APIで測れる同等の量は gallopAudit 経由の `|clipFootSpeed(cadence) − speed|`（clipFootSpeed = cadence × クリップ実測ストライド長 7.03m）であり、これを (2) として検証した。実測：16.5 m/s で誤差 ≈ 0（cadence がクランプ域内では恒等的に 0）。なお v17 は実写系クリップのため接地区間内の瞬時速度にはうねりがある。クリップ自体の接地区間平均は FL 16.46 / FR 15.99 / HL 15.77 / HR 15.89 m/s（公称 16.74 m/s、gallop-sync.js の較正どおり数%の残差）で、これは (2) の対象外として報告に留める。

### 移植B：馬体分離パス（renderer.js）

- 方式：描画直前に、馬体矩形（前後 2.30m × 左右 0.62m、両頭の進行方向フレームで判定）の交差を解消する最終分離パスを入れ、最悪ペアのクリアランスを毎フレーム `RACE_SCENE_AUDIT.minBodyClearance` に監査として露出（発火有無は `bodySeparationFired`）。
- v18 形式（両フレーム独立テスト＋5ラウンド）では解消できない配置が v17 の汎用コースに2種あったため、2フェーズ構成に変更した：
  1. 完全一致ペア：汎用コースでは pack が同一状態の2頭を返すことがあり（ジャパンカップ再現ID 20261129、50%地点で中心距離 0.000、クリアランス −0.6196）、両フレームで符号が不定になり押し分けが相殺する。→ 平均進行フレームでの単一テスト＋符号のタイブレークで解消。
  2. 単縦ペア：時計 9.656 秒で横ずれ約 0.01m の単縦列ペア（−0.6186）。両フレームの横方向符号が逆で押し分けがほぼ相殺し、60ラウンドでも −0.6186 のままだった。→ フェーズ1を「ペア平均フレームでの緩和（最大60ラウンド）」とし、フェーズ2に「厳密（両フレーム）指標での全ペア仕上げ掃引（margin +0.002、Gauss-Seidel、最大400掃引）」を追加。
- 実測：
  - 京都（pack レース）：全サンプルで無発火。kikka-browser の「描画位置と pack 状態の一致 < 0.001」は従来どおり成立。
  - ジャパンカップ（汎用東京・18頭）：シーク走査21点（5%刻み）で全点 ≥ 0（最密点で約 0.000–0.020、ゲート 0.580）。16倍速の全レース再生で記録した監査64フレームの最小値は +0.0020、負フレームなし。移植前の最小値は −0.6196 だった。
- tests/mobile-browser.mjs には、カット確認・追跡サンプル・脚サンプルへの `minBodyClearance >= -0.001` アサートと、ジャパンカップ（390×844、シーク5点＋再生30フレーム）の監査ブロックを最小限追加した。

### テスト変更の理由（行動ゲートの緩和はなし）

| テスト | 変更 | 理由 |
|---|---|---|
| smoke | index.html の renderer import アサートを、切替形（既定 `'./renderer.js?v=`、`?engine=v18` で `'./renderer-v18.js?v=v18.1'`）へ更新 | 本追記のエンジン切替（既定 v17・v18 任意選択）を仕様とするため。参照先の妥当性という目的は維持 |
| smoke | 移植Aの監査ブロックを追加 | 上記 (1)(2) の回帰防止 |
| mobile-browser | minBodyClearance アサート群とジャパンカップ監査ブロックを追加 | 移植Bの回帰防止。既存サンプルへの追加は監査フィールドの読み取りのみ |
