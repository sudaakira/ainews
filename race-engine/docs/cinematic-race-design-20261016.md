# CINEMATIC RACE 3D — 実装指示書・実装記録（2026年10月16日）

## 目的
「予想分析UIの装飾」ではなく、レース映像の実体をアニメ競馬ゲーム風の**オリジナル3Dライブ演出**へアップグレードする。手動の視点切替は廃止し、全頭のシミュレータ位置・着順に追従するオートディレクターが映像を自動的に構成する。特定の既存ゲーム作品の素材・画像・商標・キャラクターは流用しない。

## 絶対不変（計算・馬券予想）
- `core/factors.js`, `core/regression.js`, `core/simulator.js`, `races/*.js` と予想データの**計算と採点は変更しない**。
- `horseProgress(no,clock)`, `LIVE.duration`, `LIVE.clock`, `LIVE.visualTime`, 順位並び替えは従来の共通エンジンから読み取るだけ。演出側で通過・追い越し・着順の結果を作らない。
- 枠番号とJRA騎手帽色は `core/jockey-caps.js` をそのまま利用。馬番・勝負服との混同を起こさない。
- 距離・コースの3D形状は従来どおり模式図。京都芝2000mの実測コース再現や競馬の物理エンジン実装ではない。
- ギャンブルの確率・モデル内勝率は未校正。ゲーム調演出を統計的妥当性や的中保証として使わない。

## フェーズと自動カメラ
| Phase | 進捗 | 構図 | ライブ演出 |
|---|---|---|---|
| GATE IN | 発走前 | ゲートを見渡す低め斜め横 | 日本語字幕・シネマ枠 |
| BREAK AWAY | ～3.5% | ゲートに並走する発走ショット | 芝チップと発走タイトル |
| FULL GALLOP | ～40% | 先頭集団を横から追う | 追走感と競馬場群衆 |
| THE CHASE | ～70% | 馬群と外ラチを俯瞰 | 展開を見やすい大きい構図 |
| FINAL TURN | ～83% | 馬群へ徐々に寄る斜めショット | コーナーの進出感 |
| LAST 400 | ～96.5% | 低い追走、先頭2頭を追う | 流線・馬体強調・VSテロップ |
| TO THE LINE | ゴールまで | 先頭の前方からの正面競り合い | 大きな決着演出 |
| PHOTO FINISH | ゴール後 | 勝馬にピントを合わせる寄りカット | 実シミュレーション順位で勝者、紙吹雪 |

進捗は `clock / duration` から求め、固定的な脚本で**架空の追い抜きは作らない**。カメラは馬群の先頭座標 `path(lead.p)` とレース順に追従する。

## 3Dシーン演出
- `assets/race-cinematics.js` — Three.js専用演出モジュール。汎用コースに奥行きのあるスタンド、屋根、観客の `InstancedMesh`、日差しと縁取り光、細かい芝チップ `InstancedMesh`、先頭争いの発光ストリークを配置。
- 17頭それぞれの根本モデル位置だけを読み、脚元の芝、スピード軌跡、光輪を更新。物理進行・`horseProgress` を書き換えない。
- `assets/horse-anime.js` — 騎手の `rider` 部品をアニメーション用に公開。従来の枠色のヘルメットと馬の専用色を維持。
- `assets/chibi-gallop.js` — 最終直線のみ脚振り幅と騎手の前傾を少し強める**視覚的モーション**。走行速度や順位は一切変えない。
- `renderer.js` — 手動カメラコードを削除。新しい監督モジュールで `desired` と `look` と画角を自動更新。WebGL読込エラー時には従来SVG模式図へフォールバック。

## 放送演出・スマートフォン最適化
- `assets/race-cinematics.css` — 「場面タイトル」「残り直線のスピード線」「先頭2頭のVSテロップ」「勝馬発表」「紙吹雪」。画面に操作を透過させ、再生コントロールを邪魔しない。
- `index.html` — 全レースにシネマCSSと自動監督を読み込む。ブラウザキャッシュによって以前の3D馬を表示しないようにURLバージョンを更新。
- `assets/premium-mobile.js` — 手動カメラの切替ボタンを生成しない。全画面「集中表示」は任意だが、視点切替ではない。
- 画面比率の異なるiPhone/iPad/デスクトップでFOVと字幕サイズを調整。小画面では馬名の文字切れや過度な画面占有を防止。
- CSS `prefers-reduced-motion` に対応。軽量WebGL描画のため観客・芝をインスタンス化し、パーティクル数をスマートフォンで削減する。
- 実レースの録画や公式中継ではなく、仮想レースの演出であることを画面に明記する。

## バージョンと対象
- 共通エンジン `race-engine/index.html` から読み込むので、秋華賞以外の既存レース・以後の新規レースにも反映。
- 旧カメラ「全景／ゲート／追走／馬アップ／ゴール前」のユーザー向けメニューは不要。2DはWebGL障害時の自動フォールバックとして維持。
- パッケージ化されたアニメーション映像ではなく、従来の位置・順位データをリアルタイム描画するブラウザベースのThree.js映像。

## 合格基準
1. `node race-engine/tests/smoke.mjs` が成功。
2. 旧モデル `races/shuka-2026.js` と数理用 `core/factors.js`, `core/regression.js`, `core/simulator.js` のblob SHAが改修前から不変。
3. 秋華賞17頭の乱数seedと採点・出現率が一致。
4. 全8枠のJRA騎手帽色は正しく、勝負服とは独立。
5. 全7つの走行場面とゴールの字幕・先頭争いが、`clock` に追従して表示される。
6. モバイルWebGLではカメラ視点を手で変える必要がない。SVGフォールバックで再生が止まらない。
7. GitHub Actionsで自動テストとPages公開が成功。
8. 実機iPhoneでの音声・フレームレート・描画崩れ・ブラウザコンソールの目視検証は、別途確認対象（CIのみで実機動作を保証しない）。

## Ver.5：かわいい馬体＋16倍速基準の映像コンテ（2026-10-16追加）

目的：ウマ娘の**映像文法**（「レース展開を理解する客観ショット」→「接近する主役を見せる寄りショット」）を参考にしつつ、既存IPの素材やキャラクターは使わず、オリジナルのポニー競馬映像として実装。技術情報は Cygames 公式の公開コンテ事例 <https://speakerdeck.com/cygames/umaniang-puriteidabifalsekontezhi-zuo-shi-li-kontezhi-zuo-zhuan-ren-timufalsedan-sheng-tokiyarakutawohui-kaserukonteshu> を参照。

**16倍速優先**：芝2000mの仮想レースを約8秒で視聴する想定。従来の絶え間ないカメラ旋回を廃止し、レース進行率で切り替わる9ショット＋ゴール決着に統一する。各カットは視点情報が即座に分かる程度の0.5～1.3秒を意識する。画面の端に情報を寄せ、レース画面の中央を塞ぐ中央巨大字幕・デュエル帯を禁止。

| 区間（進行率） | カット | 意図 |
|---|---|---|
| 0〜7% | 発走前・スタート | 馬群とゲート全体 |
| 7〜17.5% | ローアングル正面 | 馬が迫ってくる迫力 |
| 17.5〜32.6% | ロング望遠・高め | 馬群の隊列と展開 |
| 32.6〜46.9% | キャラクター寄り | 先頭と2番手の表情 |
| 46.9〜59.8% | 反対側の引き | 位置取りの変化 |
| 59.8〜73.1% | コーナー俯瞰 | 馬群を把握 |
| 73.1〜84.2% | 直線入口の正面寄り | 仕掛けと迫る追走 |
| 84.2〜93.1% | 低い前方3/4寄り | ラスト400mの叩き合い |
| 93.1〜100% | ゴール側から望遠 | 最後の競り合い |
| 100% | 確定1〜3着発表 | 原本のLIVE.rankのみを表示 |

**馬体のかわいさ**：頭をふっくら大きく、アイデカールも拡大、ほっぺに温かい色味と小さな毛束、曲線で作った微笑み、ピンクの内耳を持つ左右独立可動耳を追加。前バージョンの8位相ギャロップ・たてがみ・尻尾・騎手の動きは継続。元の勝負服と枠帽は変更しない。

**UI**：レース画面の左上に競馬場名、右上にタイマー。小さなショット名は右上の下段に置く。最終直線の対戦表示は映像最下端の薄い帯へ移し、馬体が走る中心部を塞がない。結果3着は決着後のみ画面中央に現れる。400m前の巨大文字やフルスクリーンの速度演出を廃止する。

**共通コード**：`assets/race-shotlist.js`（ショット設計）、`assets/race-cinematics.js`（ディレクター）、`renderer.js`（実際のカット切替）、`assets/horse-anime.js`（モデル）、`assets/chibi-gallop.js`（耳揺れ）とCSSを共有。未来のレースにも自動適用。

**検証**：同一オリジン配信のThree.jsが実際に読み込まれ、モバイル390x844・320x568・430x932でWebGLが見えること、表示中の2D図を隠すこと、16倍速設定で各ショットの遷移が順序通りであること、ショット名が上部38%以内・対戦表示が画面下部85px以内に収まり、1〜3着がシミュレーション確定順と一致することをPlaywrightで自動検証。スクリーンショットはActions artifactに保存。実機Safariや実際のGPU負荷は別途要確認。

**予想データ**：`races/shuka-2026.js`、`core/factors.js`、`core/regression.js`、`core/simulator.js`の変更禁止。順位結果、点数、確率に一切影響を与えない。


## Ver.8（16倍速）実装仕様：4カット・現行京都ゴール板・上位3頭の入線停止

| レース進行率 | カットID | カメラと情報 |
|---|---|---|
| 0〜18% | `start` | 17頭全頭を収める引きのカット |
| 18〜52% | `second-turn` | 2コーナーの馬群に寄り、頭とゼッケンを見せる |
| 52〜82% | `fourth-turn` | 4コーナーの位置関係が分かる引き〜中距離 |
| 82〜100% | `straight` | 最終直線の横方向から追い、ゴール板と競り合う馬を同じ映像に収める |
| 決着後 | `result` | **1着→2着→3着**をそれぞれ約0.35秒の一時停止で示し、3頭の通過後にのみ総合着順を表示 |

- ディレクター: `assets/race-shotlist.js` ＋ `assets/race-cinematics.js`。
- **ゴール板**: `assets/kyoto-goal-board.js`。京都競馬場の2023年新設「緑×白の多重ループ・KYOTO縦文字・照明灯」を写真に基づいてプロシージャル3Dで作成。JRA公式資料 <https://kyotokeiba-grandopen.com/highlight/> および <https://www.nikkansports.com/keiba/photonews/photonews_nsInc_202304100001046-4.html> を外観参照。寸法や座標は**実測でなく模式**。
- **スタートゲート**: 発走後（仮想レース時計6秒程度）に非表示。ゴールラインには残さない。
- **写真判定演出**: `assets/photo-finish.js` の純粋な再生用タイムラインを `renderer.js` に適用。着順の一次ソースは既存シミュレータの **`LIVE.rank`** だけ。後続2頭は確定順位に従って、ゴール直前の位置から通過演出を再現。約0.35秒の静止は**実際の着差や実競馬タイムではなく、16倍速視聴のための表現**。
- **再生・巻き戻し・再スタート**: 写真判定の状態を初期化。タイムラインを100%に直接スクラブした場合は即座に確定TOP3のプレビューを表示。
- **公開条件**: 実ブラウザで17頭の3D、開始時の全頭フレーム内表示、4カット遷移、ゴール板が最終カメラに映ること、ゲートの非表示、3つの入線停止、最後のTOP3表示、モバイル1画面を検証する。
- **変更禁止**: `races/shuka-2026.js` と `core/*.js`。モデル能力、予想点、確率、勝負服、枠帽色はVer.7から変更なし。
