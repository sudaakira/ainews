# rebuild-v18 設計ノート（2026-11-03）

v17 は既存実装の外科的改善だったが、「もっと抜本的に」という評価を受け、今回は馬・歩様・競馬場環境・カメラの4要素を新規構築した。旧 renderer.js / 馬モデル（GLB）/ クリップ再生方式への互換は捨て、守ったのは契約だけである：

- core/ のシミュレーション数理（採点・回帰・着順）と pack-v1 の経路計画、`races/*.js` の設定フォーマット
- 既定値：4倍速・ばらつき3・即ゴール
- iPhone 一画面に映像・隊列・操作が収まる UI
- 枠色帽子、ゼッケンに馬名大きく、頭上ラベルなし
- 品質ゲート：蹄が地面を貫通しない、滑り足なし、先頭馬が画角内、ゲート全体が画角内、着順の決定性

旧エンジンは `?engine=v17` で参照できる（index.html の bootstrap が分岐）。天皇賞・宝塚記念の専用ページは v17 のまま据え置き（共通 index.html が主対象）。

## 1. 歩様エンジン gait-v18（新規）

ベイク済みクリップ再生を廃止し、位相の閉形式関数で全蹄ターゲットを生成する。

- ロータリーギャロップの脚順（右手前）：左後 → 右後 → 左前 → 右前 → 浮遊期。脚ごとの位相オフセットを手前ブレンドし、手前変更は浮遊期ウィンドウでのみ開始する。
- **接地ロック**：接地期の蹄は、対地速度がちょうどゼロになるよう馬体相対速度を −speed に固定。ストライド長／ケイデンスは速度から導出（基準ストライド 7.03m、ケイデンス = clamp(speed/7.03, 1.30, 2.78)）。滑りは調整ではなく構造でゼロ（監査値 slipRatio ≡ 1、数値検証でも dz/dphase = −strideLength が完全一致）。
- **位相はレース時刻にロック**（実況視聴フィードバック対応）：旧設計は歩様位相を実時間ベースの visualTime で進めていたため、4倍速では脚の回転が走行速度の約1/4しかなく「ノロい・走っていない」見た目になっていた。v18 では位相増分 = レース時計の増分 × ケイデンスとし、再生倍率によらず接地蹄の対地速度ゼロと脚の実回転数を両立させた（数値検証：4倍速相当の時計進行で位相進行 = ケイデンス×レース秒、接地蹄の対地速度 0.000）。シーク時はレース時計から位相を決定論的に再導出する。
- 背骨のバウンス／ピッチ／屈曲、頸の伸縮、たてがみ・尾の遅れ揺れ、追い切りパルスを位相連動で合成。
- 純粋関数 `computeGaitFrame({phase, lead, speedMps})` が監査データ（蹄位置・接地・浮遊）を返すため、gait-lab の位相シークが完全再現できる。

## 2. 馬モデル horse-v18（新規）

CC0 の GLB を廃止し、関節点間を楕円体ボーンで結ぶ手続きモデルに置換。

- 実測プロポーション：体高約1.64m、肩・股関節を支点に前肢（肩→肘相当→膝→球節→蹄）、後肢（股→飛節→球節→蹄）を2骨IKで解く。IK はターゲット自体を到達範囲にクランプするため、監査対象の骨長は全位相で厳密に不変。
- 背骨は2節屈曲＋ピッチ、頸は2節で伸縮、頭部は耳・目・鼻まで造形。たてがみ4節・尾3節は遅れ揺れ。
- 毛色は馬ごとに決定（鹿毛・黒鹿毛・栗毛・芦毛・青毛＋流星／作／鼻白などの顔白斑、脚のソックス）。勝負服は無地・縦縞・横縞・ダイヤ・星・サッシュ・格子をキャンバス生成、帽子は枠色（面分割パターン対応）。ゼッケンは白地に大きな馬番＋馬名。
- 騎手は関節駆動：競走姿勢では重心をき甲寄りに置き、手は頸元（手綱が口元までを橋渡し）、鐙は短く、鞭は右手に持ち最終直線の追い切りパルスでのみ控えめに振る。
- 監査（tackAudit）は実測ベース：鞍下の支持ギャップは馬体フレームで計測（0.013–0.041m）、太ももとゼッケンの干渉は実ジオメトリから 0、鐙位置はき甲の後方 0.46–0.48m。

## 3. 競馬場 course-v18（新規）

- 芝は手続きテクスチャ（刈り込みストライプ＋微細ノイズ）＋内側の荒れを頂点カラーで表現。内外ラチは連続バンド＋柱（京都は外コースの膨らみに追随し、`offsetPoint(t,outer(t)-14,.9)` で柱を打つ）。
- 発馬機は馬ごとに前扉がバネで開く詳細モデル（番号プレート、屋根、バナー）。ゴールは京都＝共有モジュールのゴール板（far側）、他会場＝v18 のゴールモニュメント。ハロン棒・距離標は共有モジュールを再利用。
- スタンドは屋根付き6段＋観客420点のインスタンシング、木々110本、雲スプライト、遠景シルエット（山並み／市街）を霧で馴染ませる。京都は池とターフビジョン（ライブキャンバス）を共有モジュールで配置し、3コーナーの下りはコース標高そのものに反映済み（kyotoHeight）。
- 遠景シルエットは当初 490m 圏に置いたが、東京のゴールカメラ（原点から約550m）がシルエット内部に入り込み画面全体が単色になる不具合をジャパンカップの目視確認で発見。リングを 900×800m へ拡大し、寸法も比例拡大して解消した（全会場のカメラ到達範囲の外に置くのが原則）。
- 汎用コース（東京など）も同じ環境システムで生成する。

## 4. カメラ camera-v18（新規）

- 確定済み5ショット（発走は横／1コーナー低く／向正面は寄りの横／4コーナー前斜め／ゴールは水平の横）を、テレビ中継の実行で：ポーズは最小ラチ外クリアランスで組み、被写体が画幅の60–72%を占めるようズーム決定。カット内はロックド・レールドーリー（先頭馬と並走しコース接線に剛体回転、レンズ固定）。先頭馬の余白はレンズシフトで光学的に作る。4コーナー（阪神除く）は固定の出口カメラ＋パンで、進入時に全アークを先行合成する。
- ラチ監査は実際に描かれる外ラチに対して行い、侵入する場合は例外を投げる（黙って越えない）。
- 芝チップは先行3頭の蹄元から小規模に飛散（InstancedMesh 54枚、モーション削減設定では停止）。

## 5. renderer-v18

- ACES トーンマッピング、スカイドーム、単一シャドウカスケード（先頭付近を追従）。
- **適応品質**：再生中 FPS（実時間 EMA）が45を割り込む状態が続けば、ピクセル比→影解像度→影オフの順に4段階で落とし、57超が続けば戻す。状態は KYOTO_RENDER_STATUS.qualityLevel と監査に露出。
- **ゴール後スローリプレイ**：結果表示（着順 DOM）が確定した「後」に、別角度（低く寄りの追従）でフィニッシュ区間を 0.25× 相当で自動再生する。タップ／再生・シーク等の操作で即スキップ。シミュレーション時計と結果には一切触れない。
  - 判断：テスト契約上、ゴール直後に結果 DOM と `shot='finish'` 監査が必要なため、「結果表示の前にリプレイを挟む」原案は「結果と並行して自動リプレイ（視覚のみ）」に読み替えた。元のレース映像の流れは止めない。
- 馬の配置は pack 状態そのまま（x/z 一致を kikka テストが 0.001 で検証）。
- **非重なり（硬性要件）**：描画直前に馬体矩形（2.30m×0.62m）基準の最終分離パスを入れ、最悪ペアのクリアランスを毎フレーム `minBodyClearance` に監査する（詳細と実測値は下記「実機フィードバック3点への対応」）。pack レースでは無発火、汎用模式コースでは実際にめり込みを解消する。
- **東京競馬場の寸法再現**（`assets/tokyo-course.js`、実況視聴フィードバック対応）：1周 2083.6m、直線 525.9m、左回り、幅 29m を寸法どおりに再現し、最後の直線の坂（残り約460m→160mで約2mの上り）を標高に反映。2400m（ジャパンカップ／東京優駿）のスタートはゴール手前 316.4m の直線上に置かれ、馬群はゴールを一度通過してから1周する実物どおりの構成。スタンド（フジビュースタンド）と内馬場ターフビジョン（時計・先頭馬をライブ表示）も配置。京都と同じメトリック経路方式で、東京の芝 1400–3400m の全レースが対象（ダートは従来どおり汎用経路）。

## テスト変更（理由つき）

行動面の品質ゲート（蹄高 > -0.003、飛行位相で全蹄浮上、骨の伸縮なし、ゲート画角、先頭馬画角、頭上ラベルなし、着順決定性、隊列一致）は全て維持。変更はバージョン固定の識別子と、v18 の実装方式に起因するもののみ：

| テスト | 変更 | 理由 |
|---|---|---|
| smoke | 参照先を renderer-v18 / horse-v18 / gait-v18 / camera-v18 / course-v18 に差し替え。GLB 検証節を「GLB・クリップを持たないこと＋手続き識別子」に置換 | v18 が標準エンジンになったため。資産の実在確認という目的は維持 |
| smoke | ソース構文チェックで export 文も剥がすよう拡張 | v18 ソース群が名前付き export を持つモジュールになったため（検査自体は不変） |
| kikka-2026 | カメラ import を race-shotlist → camera-v18 | 共通エンジンのカメラが v18 になったため |
| mobile-browser | モデル／歩様／タック識別子を v18 に更新。body の triangles は originalTriangles×16 → 等倍に | v19 のスキンメッシュ変形（16バリアント前提）が v18 では存在しないため。頂点・三角形の予算上限（<30000）は維持し、下限は実測 4052 頂点に合わせて >3000 に |
| mobile-browser | 鐙位置の範囲を (-.12,.20) → (.30,.60) | v19 ジオメトリ固有の値だった。v18 の実測プロポーションでは鐙革の支点はき甲の後方約0.47mが正しく、実測 0.46–0.48 が入る |
| mobile-browser | スクリーンショット名 sprint-v19 → sprint-v18 | 記録上の命名のみ |
| kikka-browser | モデル識別子のみ v18 に更新 | 同上 |

takarazuka / tenno の専用ページとテストは v17 のまま無変更で合格。

## 計測（390×844、SwiftShader）

SwiftShader では絶対 FPS は意味を持たないため、予算管理と相対比較で示す。

- 描画予算（自分で設定）：ドローコール ≤ 1300、三角形 ≤ 300,000（18頭＋環境）。内訳の目安は馬1頭あたり約62コール＋環境約130＋影パス。
- 実測（秋華賞・17頭）：発走 1032コール／200,686三角形、1コーナー 680／135,481、向正面 539／127,489、4コーナー 1006／185,435、ゴール 293／92,489。ジャパンカップ（東京・18頭）では向正面相当で 1243コール／207,580三角形が最大。いずれも予算内。
- 同条件の再生 FPS：v18 約1.8 vs v17 約0.4（SwiftShader 相対値）。手続きモデルはスキニング GLB よりソフトウェア描画で軽い。実機 iPhone では適応品質が段落ちを担う。
- 馬1頭の body 監査：4052 頂点／5648 三角形。

## 実機フィードバック3点への対応（2026-11-03 追記）

公開版 v17.1 への実機視聴フィードバック（①馬の動きがノロい・走って見えない ②馬同士が重なる ③東京競馬場の完全再現）を受け、v18 の必須要件として組み込んだ。

### 1. 歩様位相のレース時刻ロック（最重要）
- 旧設計の欠陥：app.js の LIVE.visualTime は dt×(1+.13·log2(rate))（4倍速で約1.26倍）しか進まず、歩様位相を実時間で進めていたため、4倍速では脚の回転が対地移動の約1/4で「滑空」して見えた。
- v18 の対応：歩様位相の進行を **レース時計の増分 × その瞬間の対地速度から導出したケイデンス** に完全同期させた（updateGallopV18）。16倍速のストロボは早送りの本質として許容し、「遅くする」妥協は入れていない。
- 監査の追加：
  - gait 監査に `groundSpeedError`（|ストライド長×ケイデンス − 速度|、構成上 0）を追加。
  - レンダラーの RACE_SCENE_AUDIT に `gallopSlipError`（ライブ実測：前後フレームで接地が続いた蹄の対地速度の最大値）を追加。手前変更中の馬と、位相進行が接地窓を超えたフレーム対（低fps時に1ストライド先へ正しく再接地したケース）は測定から除外する。
  - smoke テストに倍率4・16の実測検証を追加：1フレームの位相進行が cadence×(rate/60) と完全一致すること、接地蹄の対地速度誤差の最大値が 0.02 m/s 未満であること。
- 検証結果：ノード実測で対地速度誤差の最大 **1.4×10⁻¹¹ m/s**（倍率4・16とも、サンプル4439件）。ライブ実測（SwiftShader、秋華賞・菊花賞の再生サンプル）では最大 0.06–0.11 m/s（コーナーでのヨーと速度変化による残差）。

### 2. 馬同士の非重なり（硬性要件化）
- 対応：描画直前の最終分離パスを、中心間距離ではなく **馬体矩形（前後2.30m×左右0.62m、両頭の進行方向フレームで判定）** 基準に強化した。交差ペアは最小侵入軸（通常は左右）へ最大5ラウンドの緩和で押し分け、毎フレーム最悪ペアのクリアランスを `minBodyClearance` として監査する（負値＝めり込み）。
- テスト追加：mobile-browser の追跡サンプルとスプリントサンプルで、全フレーム `minBodyClearance >= -0.001` をアサート。
- 検証結果（再生サンプルの最小値）：秋華賞 +0.487m、菊花賞 +0.466m、ジャパンカップ +0.221m（いずれも pack 保証の範囲内で分離パスは無発火）。汎用模式コースのスワンSでは模式図の急カーブで pack 写像が圧縮され、分離パスなしでは −0.256m のめり込みがあったが、分離パスで **−0.0003m（実質ゼロ）** まで解消した。

### 3. 東京競馬場の完全再現
- `races/japan-cup-2026.js` の courseView を専用ビュー **`tokyo-2400`** に差し替え（従来の会場・距離ベースの判定も併用し、東京芝1400–3400mの他レースも同じ再現を使う）。
- 寸法再現（assets/tokyo-course.js）：Aコース1周 2083.6m、幅 29m、直線 525.9m、左回り。標高はホームストレッチの上り坂（残り約460m→160mで約2mの上り、いわゆる心臓破りの坂）を中心に実プロファイルを再現（描画実測：先頭馬の高さが向正面 0.01m → ゴール 2.02m）。
- 発走地点：2400m は「1周＋316.4m」のため、スタートはゴール手前 316.4m の直線上に置かれ、馬群はゴール板を一度通過してから1周する（JRA寸法からの必然。なお「ゴール板先・1コーナー手前」のスタートは芝2000m（天皇賞・秋）のもので、本モジュールでも2000m時はゴール先83.6m・1コーナー入口に正しく置かれる）。
- ランドマーク：フジビュースタンド（サインに明記）、内馬場のターフビジョン（時計・先頭馬をライブ表示）、ゴールモニュメント、**内馬場のダートコース**（芝コース内側の帯を新たに追加）を配置。
- app.js のモデル注記にも東京の寸法再現である旨の分岐を追加（従来は「汎用模式図で再現しません」と誤って表示されていた）。

## 未達点・妥協

- 天皇賞・宝塚記念の専用ページは v17 のまま（本変更の対象外として据え置き）。
- ゴール後リプレイは「結果表示の前」ではなく「結果表示後・視覚のみの自動アンコール」。理由は上記。
- 4コーナー固定カメラは進入直後、馬群が小さく映る（v17 から続く契約：fov 18–36、固定位置、先頭馬の中央安全域）。カット後半で馬群が近づくと解消する。
- ドローコールは馬1頭あたり約60（関節パーツ分割のため）。予算内だが、実機 iPhone での実影負荷は未検証（v17 時点からの継続課題）。適応品質の最終段で影を切れるようにしてある。
- 騎手の手は頸元まで（手綱で口元と接続）。口元まで手を伸ばす造形ではない。
